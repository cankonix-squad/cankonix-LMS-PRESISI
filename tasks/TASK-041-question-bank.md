## Data Model / Persistence
`QuestionBank`; `QuestionType`; `Question`; `QuestionVersion` (version, stem, scoringRule JSON, explanation, difficulty/topic metadata); `QuestionOption` tied to version with isCorrect/value kept server-only.

## API / Application Contract
CRUD banks/questions; create new version; read educator views. Student-safe projection separate.

## Business Rules
Edit published/used question creates new version. Historical attempt references version. Correct answer/explanation never in active student payload.

## Acceptance Criteria
[ ] version immutable; [ ] student DTO leak test; [ ] options/version tests; [ ] checks green.

## Aturan Implementasi Wajib

- Alur backend: Controller → Application Service → Domain/Business Logic → Repository → Prisma → PostgreSQL. Controller tidak boleh mengakses Prisma langsung.

- Setelah implementasi dan verification yang tersedia berhasil, ubah status task menjadi `REVIEW`, update `MASTER-CHECKLIST`, lalu STOP. Codex tidak boleh menandai `DONE`.
